# 흐름 · Android 연구 프로토타입

시간표, GPS, 앱 사용정보와 선택적 결제 알림으로 모든 관측 구간에 수업·공부·식사·이동·휴식 중 가장 그럴듯한 활동을 자동 추정하고, 신뢰도가 높지 않은 구간만 EMA로 확인하는 Android 앱입니다. 목표는 **활동 기록의 정확도와 사용자 입력 부담을 함께 평가하는 것**입니다.

## 실행

- Android 9(API 28) 이상. Kotlin 네이티브 앱, SQLite 로컬 저장소.
- Android Studio에서 이 폴더를 열고 Gradle 동기화 후 실행합니다.
- 개발 환경: Java 17 이상, Android SDK 35, Build Tools 35.0.0, Gradle Wrapper 8.9.
- `local.properties`에 개발 PC의 `sdk.dir`을 설정합니다. 이 파일은 Git에 포함하지 않습니다.
- Windows 명령:

```powershell
.\gradlew.bat -g .gradle-user-home :app:assembleDebug
.\gradlew.bat -g .gradle-user-home :app:testDebugUnitTest :app:lintDebug
.\gradlew.bat -g .gradle-user-home :app:connectedDebugAndroidTest
# 이미 켜진 전용 에뮬레이터에서 adb로 직접 검사 (UTP 다운로드 불필요)
.\scripts\verify-device.ps1 -Serial emulator-5556 -Offline
```

APK: `app/build/outputs/apk/debug/app-debug.apk`. 디버그 APK는 연구 파일럿용이며 스토어 배포용 서명이 아닙니다.

## 사용 순서

1. **시간표 → 학기 기간 변경**에서 실제 학기 기간을 지정합니다.
2. 에타 시간표 전체 이미지를 저장하거나 캡처한 뒤 **시간표 이미지 가져오기**를 누릅니다. Android 이미지 공유 대상으로 ‘흐름’을 선택해도 됩니다.
3. 한국어 OCR이 인식한 요일·시간·과목·장소를 원본과 비교하고, 틀린 항목만 수정해 저장합니다.
4. 기록 시작 시 **자동 장소 연결**을 허용합니다. 학교 이름·좌표·건물 이름을 입력하지 않습니다. 위치가 잡히면 공개 지도에서 주변 학교·기숙사·건물을 가져옵니다. **설정 → 자동 장소 인식 → 주변 장소 지도 보기**에서 확인할 수 있습니다. 지도 오류를 직접 보정하는 기능은 고급 설정의 선택 사항입니다.
5. 위치, 앱 사용정보, 알림 권한을 선택적으로 연결한 뒤 **수집 시작**을 누릅니다. 위치 권한은 수집 시작에 필요합니다. 앱 사용정보나 알림이 없으면 해당 기능만 제한됩니다.
6. **오늘**에서 기록을 확인하고 **EMA**에서 짧은 질문에 응답합니다. 필요하면 타임라인에서 활동을 수정합니다.
7. **설정 → 연구 기록 내보내기**에서 JSON 파일을 저장합니다. GPS 좌표는 기본적으로 제외됩니다.

### 에타 가져오기 범위

- 에타 계정 로그인, 비공개 API, 자동 로그인, 서버 크롤링을 사용하지 않습니다.
- 현재 구현은 **이미지 가져오기**입니다. 에타 계정과 실시간 동기화하는 기능은 없습니다.
- 기기 캘린더에 들어온 시간표는 **기기 캘린더에서 가져오기**로 선택해 가져올 수 있습니다. 에타가 시간표를 해당 캘린더로 내보낼 수 있는지는 실제 에타 앱에서 확인해야 합니다.
- 캘린더 가져오기는 지정 기간의 실제 일정 발생일을 읽습니다. 반복 일정의 예외를 임의로 주간 수업으로 복제하지 않습니다. 종일 일정과 자정을 넘는 일정은 제외합니다.
- 이미지 재가져오기는 이전 이미지 수업만 교체합니다. 캘린더와 직접 입력한 수업은 유지합니다. 캘린더도 동일한 원본을 다시 가져오면 해당 원본만 교체됩니다.
- 수강 변경은 다시 가져오기로 반영합니다. 휴강·보강·온라인 수업 여부는 이미지에서 자동 알 수 없습니다.

### 이미지 인식

ML Kit의 **앱에 포함된 한국어 모델**로 기기에서 처리합니다. 요일 헤더와 시각 표시로 좌표축을 찾고, 색이 채워진 수업 칸의 위·아래 경계로 수업 시간을 계산합니다. 텍스트 높이를 수업 길이로 사용하지 않습니다.

수업 칸을 먼저 분리한 뒤 각 칸을 원본·흑백·명암 보정 형태로 읽습니다. 서로 다른 요일의 글씨가 한 줄로 합쳐지는 것을 방지하고, 인식 결과가 다른 글씨는 확인 화면에 표시합니다. 이 비교는 검증된 정확도나 확률을 의미하지 않습니다. 이미지를 서버로 보내지 않으며, 칸이 많은 표는 처리에 시간이 더 걸릴 수 있습니다.

- 표 전체, 요일, 시간축, 수업 칸이 보이는 세로 방향 이미지를 권장합니다.
- 시간축이 누락되거나 인식되지 않으면 표의 좌표 비율과 첫 요일을 지정해 다시 읽을 수 있습니다. 일부 수업만 추출됐거나 시간이 틀린 경우에도 확인 화면의 ‘시간축 다시 지정’을 사용할 수 있습니다.
- 읽힌 요일 사이의 누락된 요일은 일정한 칸 간격을 확인한 경우에만 보완합니다. 이미지 밖으로 잘린 요일은 자동으로 추가하지 않습니다.
- `9→10→11→12→1` 형식의 시간축은 오후로 이어서 읽습니다. 오전·오후를 구분할 단서 없이 `1→2→3`만 보이는 이미지는 시간축을 직접 지정해야 합니다.
- 여러 줄 과목명은 합쳐 보존합니다. ‘공학관 301’, ‘301호’, ‘NTH213’, ‘HCA 효암본관’ 같은 장소 표기가 확인될 때만 장소로 분리하며, 교수명·다른 장소 표기는 확인 화면에서 수정해야 합니다.
- 잘린 이미지, 흑백·무채색 수업 칸, 색이 이어진 연속 수업, 다른 테마·배율은 인식 실패나 병합을 일으킬 수 있습니다. 결과를 검토하고 필요한 수업을 수정·추가해야 합니다.
- 자동 추출은 확정된 원본이 아닙니다. 실제 에타 이미지의 다양한 형식에 대한 인식률 검증은 별도 필요합니다.

## 활동 추정과 EMA

- 한국 시간(`Asia/Seoul`) 기준으로 시간표와 활동 구간을 처리합니다.
- 수집이 켜진 동안 1분마다 관측을 갱신하고 5분 단위로 저장합니다. `observedFrom`과 `end`가 실제 관측 범위이며 `start`는 구간 식별용 버킷 시작입니다. 수집하지 않은 시간대를 기록으로 채우지 않습니다.
- 위치 갱신은 GPS·네트워크 제공자에 2분 간격으로 요청합니다. 실제 전달 주기는 OS·전원·신호 상태에 따라 달라집니다.
- 최근 10분 안의 정확도 100m 이하 위치를 사용합니다. 자동 장소는 닫힌 건물/학교 경계와 GPS 오차를 함께 검사합니다. 이름만 있는 점(식당·도서관·편의점 등)은 오차 범위(최대 40m) 안에 있을 때 ‘부근’ 근거로만 사용합니다. 다중 영역의 안쪽 빈 공간도 제외하며, 불완전한 경계는 사용하지 않습니다. 직접 보정은 이전 버전의 원형 영역입니다.
- 활동 추정 규칙은 아래 ‘0.5.0 · 활동 추정 엔진 재설계’를 따릅니다. 신뢰도는 규칙 수준이며 보정된 확률이 아닙니다.
- 지도에 실제 등록된 이름·별칭·`ref`를 시간표 장소와 연결합니다. 자동 연결은 문자열 시작과 다음 문자 경계를 확인하며 숫자로만 된 아파트 이름을 교실 번호와 연결하지 않습니다. `NTH` 약어가 지도에 없으면 뉴턴홀과 임의로 연결하지 않습니다. 직접 보정의 코드 연결은 공백·대소문자를 제외한 기존 부분 일치입니다. 지도에 없는 약어 대응은 운영자가 제공할 캠퍼스 데이터로 보완할 수 있으며 아직 자동으로 생성하지 않습니다.
- 새 설정은 이후 관측부터 적용하고 이전 기록을 바꾸지 않습니다. 학교에 있다는 사실만으로 출석을 확정하지 않으며, 근거가 약한 추정은 신뢰도 ‘낮음’으로 저장하고 EMA로 확인합니다. 화면 사용과 가장 오래 사용한 앱은 보조 근거로만 씁니다.
- 화면 사용 시간은 Usage Events에서 화면 상태·전경 앱 이벤트를 합산한 관측 추정값입니다. 이벤트 누락·보존 기간·OEM 차이로 시스템 화면 사용 보고와 다를 수 있습니다. 수집 구간 이전 하루의 이벤트는 경계 상태를 복원하는 용도로만 읽고 원본 이벤트는 저장하지 않습니다.
- EMA는 구간을 최소 3분 관측한 뒤 생성합니다. 기본 상한은 하루 3회, 최소 간격 90분, 알림 쉬는 시간 21:00~09:00입니다. 대기 질문은 최대 하나입니다.
- 건너뛴 질문·미응답도 생성 횟수에 포함됩니다. 동일 구간은 재질문하지 않습니다. 질문은 2시간 후 만료되며 미응답을 확인된 활동으로 바꾸지 않습니다.
- EMA와 수정 결과는 `reportedActivity`, `reportedAt`, `verification`에 저장합니다. 모델의 `activity`와 독립적으로 보존합니다. 이후 관측 갱신으로 사용자 응답이 덮어쓰이지 않습니다.
- 선택적인 연구용 검증 질문은 일부 높은 신뢰도 구간에도 생성하며 하루 최대 1회, 전체 상한 안에 포함합니다. 이는 파일럿용 체계적 표본이며 무작위·대표 표본을 통한 최종 정확도 평가를 대체하지 않습니다.

## 보관·동의

- 수집은 사용자가 시작한 위치 foreground service에서만 수행합니다. 알림과 앱 설정에서 중지할 수 있습니다.
- 자동 부팅 재시작과 중지 뒤 자동 재시작은 하지 않습니다. 프로세스 종료·OS 강제 종료 뒤에는 앱에서 다시 시작해야 합니다.
- 연구 서버, 회원가입, 웨어러블, 운동량 수집은 없습니다. 시간표 이미지·GPS 관측·앱 사용·EMA를 서버로 보내지 않습니다.
- 지도 화면은 인터넷 권한으로 OpenStreetMap 배경 타일을 요청합니다. 지도 제공자에게 표시 지역의 타일 번호와 IP 주소가 전달됩니다. 지도는 현재 위치를 지속 추적하지 않고, 사용자가 지도 화면을 열거나 이동할 때만 배경을 불러옵니다. 키·계정은 필요하지 않습니다. [OSM 타일 정책](https://operations.osmfoundation.org/policies/tiles/)에 따라 앱 식별자, HTTPS, 화면의 출처 표기와 최소 7일 타일 캐시를 사용하며 사전 다운로드 기능은 없습니다. 서비스 연결이 실패해도 이미 저장된 건물 경계는 표시할 수 있습니다.
- 자동 장소 연결은 기본적으로 꺼져 있고 처음 기록 시작할 때 별도로 선택합니다. 약 4km의 격자 범위와 IP를 `overpass-api.de`에 보내며 정확한 GPS 관측이나 연구 기록을 요청에 넣지 않습니다. 새 지역의 요청/실패 재시도는 최소 6시간 간격이고 같은 지역은 7일 캐시를 재사용합니다. 캐시는 만료 후 앱 사용 시 삭제되며 자동 연결을 끄거나 전체 삭제하면 즉시 제거합니다. 자동 장소는 기숙사 태그/이름을 분류에 이용하므로 지도 분류 오류 가능성이 있습니다.
- **공개 Overpass 서버는 이번 소규모 개발 검증 경로입니다. 참여자 대상 연구 배포/서비스 운영의 백엔드로 쓰지 않아야 합니다.** 자체 Overpass 인스턴스 또는 사용 계약을 맺은 장소 데이터 공급자로 교체해야 합니다. [Overpass 운영 정책](https://dev.overpass-api.de/overpass-doc/en/preface/commons.html)은 일반 앱의 공용 서버 의존을 지양합니다. 이 APK를 대규모 배포하지 않습니다.
- 내보내기의 `schemaVersion: 2`에 현재 장소 설정(`currentPlaceSettings`)을 추가했습니다. 장소의 중심 좌표도 좌표 포함을 선택할 때만 내보냅니다. 자동 장소 연결 여부와 출처도 포함하고, 다운로드한 전체 지도 정보는 내보내지 않습니다. 이 설정은 내보내기 시점의 설정이며 과거 구간의 장소 설정 스냅샷이 아닙니다.
- Android 백업·기기 전송을 제외하도록 설정했습니다. 데이터는 앱 내부 저장소에 보관하며 루팅 기기 보호나 별도 DB 암호화는 이번 버전의 범위에 포함되지 않습니다.
- 위치·활동·EMA는 앱 실행·수집·내보내기 시점에 30일 보관 정책을 적용해 오래된 행을 삭제합니다. 앱이 실행되지 않으면 정리도 실행되지 않습니다. 시간표는 직접 삭제할 때까지 유지합니다.
- ‘모든 데이터 삭제’는 수집을 중지하고 앱 내부 기록·장소·설정·지도 캐시를 삭제합니다. 이미 내보낸 파일은 앱이 삭제하지 않습니다.
- 실제 연구 참여자 운영 전 동의 절차, 연구 설계, 배터리·누락률과 EMA 부담을 검증해야 합니다.

## 주요 파일

- `core/InferenceEngine.kt`, `core/MapPlace.kt`: 활동 추정(수업·공부·식사·이동·휴식), 앱 종류 분류, 지도 경계/오차 처리와 EMA 정책.
- `data/AutomaticPlaces.kt`: 공개 지도 장소 조회·기기 캐시·지도 데이터 파싱.
- `ui/CampusMapView.kt`, `core/MapProjection.kt`: 지도 표시·영역 선택·좌표 변환.
- `core/GridParser.kt`: 이미지 좌표축·수업 구간 변환.
- `data/TimetableOcr.kt`: 기기 내 한국어 OCR·칸별 재인식.
- `core/ColorBlockDetector.kt`, `core/OcrConsensus.kt`: 색상 칸·시간선 검출, 여러 인식 결과 비교.
- `data/Collectors.kt`: 앱 사용 이벤트 합산·캘린더 읽기.
- `data/LocalStore.kt`: SQLite 기록·사용자 응답·내보내기·보관 정책.
- `TrackingService.kt`: 명시적 수집·관측 갱신·EMA 알림과 응답.
- `MainActivity.kt`: 시간표 가져오기·타임라인·EMA·권한 설정.

## 0.4.0 · 선택적 결제 알림과 장소 관측

- 설정 → **결제 알림 연결 (선택)** → 설치된 결제 앱 선택 → 별도 동의 → Android의 알림 접근 허용. 이후 활동 기록을 시작해야 수집합니다. 기본은 꺼짐이며 기록 중지·앱 선택 해제·연결 끄기·OS 권한 해제 시 새 수집을 하지 않습니다.
- `NotificationListenerService`에서 선택 앱 여부와 동의/수집 시작 시각을 확인한 뒤 알림을 읽습니다. 이전 알림 목록을 조회하지 않습니다. 결제/승인/취소, 단일 원화 금액, 명시적 가맹점 필드 또는 제한된 상점 이름 형식이 함께 있어야 처리합니다. 인증·송금·출금·예정/청구·광고·실패 알림, 애매한 형식은 버립니다. 실제 토스/카드사별 알림 형식 호환성은 아직 검증하지 않았습니다.
- 가맹점, 출처 앱, **알림 게시 시각**과 승인/취소 종류만 저장합니다. 실제 거래 시각과 다를 수 있습니다. 금액은 메모리에서만 중복/취소 비교에 사용합니다. 무작위 설치별 salt와 SHA-256으로 비교용 지문을 만들고, 금액·원문·카드/계좌번호·알림 키 원문은 저장/내보내지 않습니다. 금융 로그인·SMS·과거 거래내역·토스 계정 API는 사용하지 않습니다.
- 같은 가맹점/금액 승인 알림을 90초 안에 여러 선택 앱에서 받으면 중복으로 처리합니다. 동일 알림 갱신은 5분 안에 중복으로 처리합니다. 같은 가맹점/금액의 취소가 24시간 안에 있으면 관련 승인 근거를 보수적으로 제외합니다. 거래 식별자가 없어 동일 금액의 별개 결제도 제외될 수 있습니다. 이 경우 자동 식사 추정을 철회하고 대기 EMA를 만료시키며 이미 입력한 사용자 응답은 보존합니다.
- 편의점은 **구매 추정**으로 기록하고 식품 구매나 섭취를 단정하지 않습니다. 식사 추정은 식당으로 분류된 가맹점, 지도 이름의 연결, 결제 부근 위치, 최소 2분의 연속 장소 관측이 함께 필요합니다. 수업·기숙사 근거를 결제로 덮어쓰지 않습니다. 최신 위치가 없거나 장소를 떠났다면 현재 식사로 추정하지 않습니다.
- 닫힌 건물 경계는 GPS 오차 원이 내부에 있을 때 사용합니다. 경계 없는 POI는 GPS 오차를 포함해 50m 안에 있을 때 **부근** 관측으로만 표시합니다. 연결 후보가 여러 개이면 미확인입니다. 위치 간격 5분 초과·장소 이탈·수집 재시작은 체류 관측 구간을 끊습니다. 첫/마지막 GPS 사이의 관측 범위를 표시하며 실제 입장/퇴장 또는 먹은 시간은 아닙니다. 배달·포장·대기·대리 결제·알림 누락/지연은 여전히 구분되지 않을 수 있습니다.
- 결제/장소 카드의 체류 해석은 **현재 지도 캐시**로 계산합니다. 지도 연결 해제·캐시 만료·다른 지역의 캐시 교체 이후에는 과거 체류 해석이 없어지거나 달라질 수 있습니다. 활동 구간에 이미 저장된 추정/EMA는 독립적으로 보존합니다.
- 결제 알림은 실행/수집/내보내기 시 30일 정책으로 정리합니다. 연결 끄기는 기존 기록을 유지하고, 결제 기록만 삭제하면 결제 수집도 끕니다. 기존 활동 추정·EMA는 남습니다. 모든 데이터 삭제는 결제 기록과 설정도 제거합니다.
- 내보내기 `schemaVersion: 3`: 결제 행은 기본 제외하며 **결제 가맹점·알림 시각 포함**을 별도로 선택해야 추가됩니다. 선택 내보내기에는 현재 지도 캐시로 계산한 활동 후보와 관측 범위도 포함하며 금액/매칭 지문은 제외합니다. 결제 행 제외 시에도 활동 구간의 식사 추정 이유·장소·근거 ID는 포함될 수 있습니다. 원본 GPS는 기존의 별도 선택을 따릅니다. 결제/활동 데이터는 지도 요청에 포함하지 않습니다.

관련 코드: `core/PaymentEvidence.kt`, `PaymentNotificationService.kt`, `data/LocalStore.kt`. 알림 파서는 실제 결제 앱의 형식 변화에 따라 확장해야 합니다. 검증용 예시는 모두 합성 데이터입니다.

## 0.5.0 · 활동 추정 엔진 재설계

0.4.0까지는 엔진이 ‘수업’ 또는 ‘활동 미확인’만 출력했고, 실내 GPS 오차(보통 20~60m)가 건물 벽에 닿기만 해도 미확인으로 처리해 실제 사용에서 대부분의 구간이 미확인이었습니다. 0.5.0은 모든 관측 구간에 가장 그럴듯한 활동을 신뢰도와 함께 저장하고, ‘높음’이 아닌 구간은 확인형 EMA(“공부 중이었나요?”)로 묻습니다.

- **위치 판정 완화**: GPS 점이 건물 경계 안이면 그 건물로 봅니다(겹친 건물은 가장 작은 건물). 점이 벽 밖이어도 오차(최대 40m) 안이면 가장 가까운 건물 ‘부근’으로 봅니다. 연속 체류 시간은 이 기준으로 계산합니다.
- **수업 시간**: 화상 강의·LMS 앱 사용 → 수업(높음). 시간표 장소와 연결된 건물에 2분 이상 → 수업(높음), 단일 관측 → 보통. 이동 중 → 이동. 기숙사 → 수업(낮음, 온라인/결석 확인). 학교 안 다른 곳 → 수업(보통), 연결된 강의동이 따로 확인되는데 그 밖이면 낮음. 위치 없음 → 시간표 기반 수업(낮음). 학교 밖 → 아래 일반 규칙(낮음 상한).
- **이동**: 최근 6분 안의 두 위치가 두 오차 원의 합(최소 50m)보다 멀고 속도가 시속 2~250km이면 이동. 250m·2분 이상이면 높음, 시속 25km 초과는 차량으로 표시. 최신 두 위치가 다시 일치하면 도착으로 보고 이동을 끝냅니다.
- **장소 기반**: 도서관 → 공부(5분 이상 높음). 식당·카페(식사 시간대 07:30~09:30·11:00~14:00·17:00~20:00) → 식사, 그 외 시간 → 공부/휴식(낮음). 편의점 → 식사/휴식(낮음). 수업 없는 강의동 → 공부(자습). 일반 건물 안의 식당·도서관 지점은 건물보다 우선합니다.
- **기숙사·주거 건물**: 밤(23:00~07:00) → 휴식(화면 꺼짐이면 높음). 낮에는 앱 종류로 공부/휴식을 고르고 근거가 없으면 휴식(낮음). 지도 `building=apartments/house/residential` 등은 ‘주거 건물’로 분류합니다.
- **앱 사용**: 가장 오래 쓴 앱을 패키지 이름 규칙과 Android `ApplicationInfo.category`로 강의/학습/여가/메신저/지도로 분류해 보조 근거로 씁니다. 원본 앱 목록은 저장하지 않습니다.
- **결제**: 결제 근거 식사 추정은 기본 추정이 수업·이동·식사가 아니고 신뢰도가 높지 않을 때 적용합니다. 기숙사 제외 규칙은 유지합니다.
- 위치·앱 근거가 모두 없으면 여전히 ‘활동 미확인’입니다. 수업 일정이 겹치면 연결된 건물이 있는 수업을 고르고 신뢰도를 보통 이하로 제한합니다.
- 검증: 이 저장소의 JVM 단위 테스트 100개 통과(기존 80개를 새 정책에 맞게 갱신 + 실내 GPS 오차·이동·도서관·식사·기숙사 밤·온라인 수업 등 20개 추가). 이번 변경의 APK 빌드·기기 테스트는 실행하지 않았습니다. 실제 휴대폰에서의 정확도는 EMA 응답으로 평가해야 합니다.

관련 코드: `core/InferenceEngine.kt`(DeviceContext·AppCategory·이동/체류 판정), `core/MapPlace.kt`, `TrackingService.kt`, `test/.../ActivityInferenceTest.kt`.


## 0.6.0 · 카카오 장소 보강과 건물 직접 고치기

OpenStreetMap에는 학교 안 식당·카페가 거의 없고, 건물 이름·용도가 오래된 경우가 있습니다(예: 한동대 ‘아이하우스’가 OSM에는 기숙사로 남아 있지만 카카오는 ‘글로벌하우스’, 네이버는 ‘SW타운’으로 표기).

- **카카오 로컬 보강(선택)**: `local.properties`에 `KAKAO_REST_KEY=...`(카카오 개발자 REST API 키, 카카오맵 사용 설정 ON)를 넣고 빌드하면 켜집니다. 키는 Git에 포함되지 않습니다. 키가 없으면 0.5.0과 동일하게 OSM만 사용합니다.
  - 요청: OSM에서 찾은 학교마다 학교 이름 키워드 검색(최대 45개)과 음식점(FD6)·카페(CE7)·편의점(CS2) 카테고리 검색(최대 5페이지)을 **학교 중심 좌표** 기준으로 보냅니다. 참여자의 GPS 좌표·기록은 보내지 않으며, 카카오에는 학교 이름·좌표와 IP가 전달됩니다.
  - 병합 규칙: 건물 경계 안의 학교부속시설이 하나이면 그 이름을 별칭으로 추가합니다(OSM 이름이 없을 때만 이름으로 사용). 카카오 분류가 ‘기숙사’면 기숙사, ‘도서관’이면 도서관으로 바꾸고, 이름 없는 일반 건물에 학교부속시설이 있으면 강의동으로 봅니다. 카카오는 기숙사도 ‘학교부속시설’로 두는 경우가 많아 OSM의 기숙사 분류를 내리지 않습니다. 식당·카페·편의점은 OSM에 같은 이름의 점이 40m 안에 없을 때 추가합니다.
  - 좌표→도로명 건물명은 캠퍼스 전체가 하나의 주소(‘한동대학교’)로 나와 사용하지 않습니다.
  - 새 지역 조회 시 함께 받고, 기존 OSM 캐시에는 키 설정 후 최대 6시간 간격으로 한 번 보강합니다. 결과는 OSM 데이터와 같은 7일 캐시에 저장됩니다. 대규모 배포 시 APK의 키는 추출될 수 있으므로 서버 경유 호출로 바꿔야 하며, 카카오 이용약관의 결과 저장 조건을 확인해야 합니다.
- **건물 직접 고치기**: 설정 → 자동 장소 인식 → 주변 장소 지도에서 건물을 누르면 이름과 용도(강의동·도서관·기숙사·식당·주거·기타)를 바꿀 수 있습니다. 지도 원래 이름과 카카오 별칭을 함께 보여 주며, 원래 이름은 별칭으로 남아 시간표 강의실 연결에 계속 쓰입니다. 수정은 이 휴대폰에만 저장되고 이후 관측부터 반영되며, 내보내기의 `currentPlaceSettings.placeCorrections`에 id·이름·용도만 기록됩니다.
- 검증: JVM 단위 테스트 108개 통과(실제 카카오 응답 형태를 본뜬 병합·보정 테스트 8개 추가). 카카오 API 응답 형식은 PC에서 실제 키로 조회해 확인했습니다.

관련 코드: `core/PlaceEnrichment.kt`, `data/KakaoLocal.kt`, `data/AutomaticPlaces.kt`, `ui/CampusMapView.kt`(건물 탭), `MainActivity.kt`(건물 정보 고치기).
