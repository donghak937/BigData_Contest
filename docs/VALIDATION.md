# 첫 버전 검증 결과

시간표 인식 보완 변경의 검사 결과는 아래 ‘시간표 파서 보완’에 별도로 기록합니다. 아래 기기 검사·화면 검증은 최초 버전의 결과이며, 변경 버전의 실제 에타 이미지 인식률을 입증하지 않습니다.

검증일: 2026-10-03 (한국 시간)

## 통과한 검사

- `assembleDebug`: 설치 가능한 디버그 APK 생성.
- `lintDebug`: 오류 0개. 경고 8개는 이전 target/dependency 버전 및 한국어 고정 UI·좌표 숫자 표시 관련 항목입니다. 배포 전 대상 SDK·라이브러리와 다국어 정책을 검토해야 합니다.
- JVM 테스트 16개 통과: 활동·장소 추정, 결측·오래된 위치·겹친 일정, EMA 상한, 시간표 좌표축과 첫 시각 누락 회귀 조건.
- Android 기기 테스트 8개 통과: 응답 보존, 건너뛰기, 질문 중복·만료, 원본별 재가져오기, 좌표 제외 내보내기, 보관 정책, 시작 화면, 실제 한국어 OCR.
- 전용 Android API 37 에뮬레이터에서 설치·시작 및 화면 표시 확인.
- 이미지 선택 → 한국어 OCR → 수업 확인 → 시간표 저장 흐름 확인. 생성한 테스트 이미지에서 월요일 자료구조 09:00~10:30, 화요일 통계학 11:00~12:00을 저장했습니다.
- 위치·앱 사용정보 권한을 에뮬레이터에 부여한 뒤 foreground service 시작과 관측 저장을 확인했습니다. GPS 위치 기록과 화면 사용 시간(154,471ms)의 저장을 확인했습니다.
- 앱의 ‘수집 중지’ 버튼 실행 후 수집 상태가 꺼지고 foreground service가 종료되는 것을 확인했습니다.
- 최종 설치 앱에서 인터넷 권한이 요청 목록에 없음을 확인했습니다.

원시 테스트 출력은 `app/build/reports/device/instrumentation.txt`, JVM 보고서는 `app/build/reports/tests/testDebugUnitTest/`, lint 보고서는 `app/build/reports/lint-results-debug.html`에 있습니다.

## 남은 실제 환경 검증

- 실제 에타 시간표의 테마·배율·학교·캡처 형식별 인식률.
- 에타 외부 캘린더 내보내기 가능 여부 및 변경 전파 방식.
- 실제 휴대폰의 실내 GPS 오차, OEM 백그라운드 제한, 앱 사용 이벤트 누락과 하루 배터리 소모.
- 실제 일정 예외·EMA 응답을 이용한 활동 추정 정확도와 입력 부담 평가.
- Android 9~16 실제 기기 호환성. 에뮬레이터 결과를 실제 기기 결과로 대체하지 않습니다.

신뢰도는 규칙 기반 등급입니다. 모델 정확도나 입력 부담 감소율을 실험 전 수치로 주장하지 않습니다.

## 시간표 파서 보완

- 여러 줄 과목명 보존, 명확한 장소 표기 분리, 일정한 요일 간격에서 중간 요일 누락 보완, 잘린 바깥 요일 미추가를 검증하는 회귀 검사 6개 추가.
- 변경 버전 `testDebugUnitTest`, `assembleDebug`, `lintDebug` 통과. 총 JVM 테스트 22개.
- 일부만 추출된 시간표에서도 확인 화면에서 시간축을 다시 지정할 수 있고, 잘린 이미지의 첫 요일을 선택할 수 있도록 수정.
- 이번 변경의 기기 UI·실제 OCR 검사는 다시 실행하지 않았습니다. 실제 실패한 에타 원본 이미지가 없어, 인식률 개선 수치는 측정하지 않았습니다.

## 실제 에타 이미지로 재현한 인식 개선

사용자가 제공한 1034×1800 이미지 1장을 전용 Android 에뮬레이터의 기기 내 ML Kit 모델로 검사했습니다. 원본 이미지는 APK나 공개 테스트 자료에 포함하지 않습니다.

- 변경 전: `9→10→11→12→1` 시각 표시에서 시간축 검출이 실패하여 수업을 추출하지 못함. 요일이 다른 글씨가 하나의 OCR 줄로 합쳐지는 현상도 확인.
- 변경 후: 수업 칸 14개 모두 추출. 사람이 원본에서 별도로 읽은 정답과 비교하여 요일, 시작·종료 시각, 과목명, 장소가 모두 일치했습니다. 과목명·장소 비교 시 줄바꿈으로 생긴 공백은 제외했습니다.
- 전체 이미지의 단어를 칸별로 분리하고, 각 칸의 원본·흑백·명암 보정 결과와 비교합니다. 다르게 읽힌 글씨는 확인 화면에 표시합니다. 일치 여부는 보정된 신뢰 확률이 아닙니다.
- 시간축은 위에서 아래로 읽고, 12시 다음의 1시는 13시로 처리합니다. 시각 글씨와 표의 가로선 사이 차이는 실제 가로선으로 보정합니다.
- JVM 테스트 39개 및 Android 테스트 9개 통과. Android 검사에는 실제 제공 이미지의 14개 수업에 대한 전체 정답 비교와 생성 이미지의 OCR 회귀 검사가 포함됩니다. 빌드와 lint도 통과했습니다.
- 최종 원시 결과: `app/build/reports/device/everytime-instrumentation.txt`, `app/build/reports/device/everytime-result.txt`. 제공 원본 없이 기본 기기 검사를 실행하면 실제 이미지 검사는 생략됩니다.
- 실제 이미지 공유 → 14개 수업 확인 화면도 에뮬레이터에서 확인했습니다. 작은 화면에서 버튼이 밀리지 않도록 시간축 조정은 확인 화면 본문에 배치했습니다.
- 이 결과는 제공된 이미지 1장에 대한 검증입니다. 다른 에타 이미지의 전체 인식률을 의미하지 않습니다.

개인 시간표 원본·추출 문서·확인 화면과 해당 이미지의 회귀 정답은 로컬에만 보관하며 공개 저장소에 포함하지 않습니다. 위 검사 개수는 비공개 로컬 검사까지 포함한 결과입니다.

## 학교 지도와 기숙사 구분 (0.2.0)

- 기숙사·수업 건물을 지도에서 중심과 반경으로 등록하고 시간표의 장소 코드를 수업 건물과 연결합니다. 기존 학교 설정과 DB는 유지합니다.
- 기숙사 안 또는 GPS 오차가 기숙사 영역에 걸치는 경우 수업을 자동 판정하지 않고 활동 미확인·EMA 대상으로 처리합니다. 기숙사와 강의동이 겹쳐도 기숙사 제외 규칙이 우선합니다. 기숙사에 있다는 사실로 휴식·수면을 추정하지 않습니다.
- 학교 전체에 있다는 근거만으로 신뢰도 높음을 주지 않습니다. 높은 신뢰도는 시간표 장소와 연결된 수업 건물 안에 2분 이상 체류 근거가 있는 경우에만 사용합니다.
- JVM 56개 통과: 추가 17개는 장소별 수업 판정·기숙사 겹침·경계 오차·강의동 코드·지도 좌표 변환을 확인합니다.
- Android instrumentation은 11개 중 10개 통과, 원본 파일 인자가 필요한 기존 에타 검사 1개는 생략했습니다. 추가 기기 검사 2개는 별도 테스트 설정 파일에서 장소 저장·재읽기·수정·삭제·좌표 제외와 네트워크 없이 지도 렌더링·이동·확대를 확인합니다.
- `assembleDebug`, `assembleDebugAndroidTest`, `testDebugUnitTest`, `lintDebug` 통과. lint 오류 0개, 경고 10개(기존 8개 및 지도 draw 할당·XML 생성자 관련 경고), 정보 1개.
- 장소·좌표·기숙사 구분은 실제 학교에서 아직 검증하지 않았습니다. 실내 GPS가 두 건물을 구분하지 못하는 경우 EMA로 보완해야 합니다.
- 에뮬레이터에서 학교 지도 화면의 실제 HTTPS 배경 타일 표시와 출처 표기를 확인했습니다. 테스트 환경의 외부 DNS 실패 때문에 호스트의 임시 OSM 전용 CONNECT 프록시를 이용했습니다. 프록시는 APK에 포함되지 않으며 사용자의 휴대폰 설정에 필요하지 않습니다. 연결 실패 화면에서도 좌표·반경 저장이 가능함을 확인했습니다.
- 설정 화면에서 학교 범위를 저장하고, 기숙사 지도 중심을 끌어서 이동한 뒤 저장했습니다. 학교 좌표를 유지하면서 새 기숙사 좌표·반경이 설정 파일에 기록된 것을 확인했습니다.
- 지도는 OSM 배경만 인터넷으로 읽고 센서·활동·EMA를 전송하지 않습니다. 표시 지역 타일과 IP는 제공자에게 전달됩니다. 인터넷 권한은 0.2.0부터 추가되었습니다. 지도 타일은 최소 7일 재사용하며 사전 다운로드하지 않습니다.
- 내보내기는 schemaVersion 2에 내보내기 시점의 장소 설정을 추가합니다. 좌표 제외 옵션은 장소의 중심 좌표에도 적용합니다. 과거 구간은 기존 판정 그대로 유지합니다.

[지도 화면 예시](screenshots/campus-map.png): 테스트 좌표(서울시청 부근)의 표시입니다. 실제 사용자의 학교 위치를 의미하지 않습니다.


## 장소 입력 없이 자동 인식 (0.3.0)

- 기본 사용 흐름에서 학교 이름·좌표·반경·기숙사 이름·강의동 코드를 입력하는 단계를 제거했습니다. 첫 기록 시작 시 자동 장소 연결을 선택하며, 수집 중 정확도 100m 이하의 최근 위치가 들어오면 주변 지도의 건물 정보를 가져옵니다. 직접 보정은 고급 설정의 선택 기능으로 남겨 기존 설정을 유지합니다.
- 학교/건물의 닫힌 실제 경계와 GPS 오차를 비교합니다. 지도에 이름만 있는 점은 위치 라벨로 표시하며 건물 내부 근거로 사용하지 않습니다. 다중 영역의 안쪽 빈 공간을 제외하고 불완전한 관계 경계는 사용하지 않습니다. 기숙사와 겹친 오차, 여러 건물에 걸친 오차는 보류합니다.
- 지도에 실제 등록된 이름·별칭·ref만 시간표 장소와 비교합니다. 숫자로만 된 아파트 이름을 교실 번호에 연결하지 않습니다. 없는 NTH 등 약어를 임의로 생성하지 않으며, 약어가 없으면 수업 신뢰도를 낮추고 EMA 대상으로 남깁니다.
- 공개 예시 데이터로 한동대학교 주변 약 4km 범위를 조회해 91개 지도 장소를 읽었습니다. 이 데이터에는 기숙사 9곳, 뉴턴홀·올네이션스홀 등의 건물 경계가 포함되어 있습니다. 사용자의 실제 GPS가 아닌 공개 캠퍼스 테스트 좌표를 사용했습니다.
- 전용 Android 에뮬레이터에서 기록 시작 → 자동 연결 허용 → 이름 입력 없이 지도 91개 장소 자동 조회 → 기기 캐시 저장 → 지도 표시를 확인했습니다. 외부 DNS 제한 때문에 검사 중에만 호스트의 임시 HTTPS CONNECT 프록시를 사용했고, 테스트 후 프록시 설정과 프로세스를 제거했습니다. APK에는 프록시가 포함되어 있지 않습니다.
- 지도는 배경 타일과 별도로 건물 경계를 표시하고, 장소 이름의 겹침을 줄이며 GPS 오차 영역을 파란색으로 표시합니다. 자동 조회가 끝난 뒤 저장된 장소는 외부 연결 없이 재사용합니다.
- JVM 70개 통과(기존 56개 + 자동 장소 14개): 기숙사 우선, 건물 경계, 여러 건물, 체류, 이름만 있는 점, 지도 약어 누락, 오래된 위치, 빈 공간, 숫자 건물 이름, 기존 직접 보정 호환성 등을 검사합니다.
- Android 15개 중 14개 통과, 원본 에타 이미지 인자가 필요한 1개는 생략했습니다. 추가 4개는 실제 Android JSON 파싱·불완전 경계·연결 동의 설정·공개 캠퍼스 데이터의 기숙사 9곳과 건물을 검사합니다. 공개 지도 데이터 파일은 검사 인자로 전달하며 APK에 포함하지 않습니다.
- `testDebugUnitTest`, `assembleDebug`, `assembleDebugAndroidTest`, `lintDebug` 통과. lint 오류 0개, 경고 12개. 실제 휴대폰의 실내 GPS 구분, 지도 데이터 최신성/누락, 참여자 부담 감소와 행동 추정 정확도는 아직 실험하지 않았습니다.
- 주변 조회는 약 4km 격자 범위와 IP만 제공자에게 전달합니다. 정확한 GPS 기록·시간표·앱 사용·EMA를 요청에 포함하지 않습니다. 최대 6시간 간격의 요청과 7일 캐시, 응답 크기 제한, 실패 시 미확인 상태, 연결 해제/전체 삭제 시 캐시 제거를 구현했습니다.
- 공개 Overpass 서버는 이번 개발 검증에만 이용합니다. 참여자 연구 배포/서비스 운영 전 자체 인스턴스 또는 허가된 장소 데이터 공급자로 교체해야 합니다. [운영 정책](https://dev.overpass-api.de/overpass-doc/en/preface/commons.html), [네이버 주소 반환 범위](https://guide.ncloud-docs.com/docs/maps-reversegeocoding-api), [네이버 지역 검색 범위](https://developers.naver.com/docs/serviceapi/search/local/local.md)를 확인했습니다. 네이버 지도의 화면과 같은 모든 POI가 공개 API로 제공된다고 가정하지 않았습니다.
